§1The overview — one page, four bands

Summary answers «is the plant all right» in six numbers. Generation is nine tiles and nothing else: state ring, tag, P, rated — no PF, no frequency, no energy, no trend, because those are one screen down. Distribution is the A·B·C·D ladder in miniature with the couplers. Main loads is the half the mimic never had: one row per service group, its connected power, which busbars feed it, one pill per unit — you can count them — and how many are running. Right now that reads: one genset carries the plant, the whole lean-amine cooler bank is turning, and none of the sixteen 560 kW compressors is, which is exactly what a plant in commissioning at 01:49 should look like.

§2Load census — every group against BOTH sources

The join between the load list (Supabase) and the historian is by family and count, not by guessing a tag: the DB calls a fan MF-334-7 and the historian calls it E-334G, and nobody has published which number is which letter. What CAN be checked is that both sides carry the same number of machines in the same family — and they do, in every row. A mismatch here would mean the sheet is counting something the plant does not have (or missing something it does), so it is printed, not assumed.

§3The four status marks

RUN and STOP come from the machine itself: QRUN, or its own RunTime_Hour_Total advancing inside the window — evidence, not inference. RAW is the interesting one: the unit publishes a packed status word (QdwState/QwState) and nobody has the bit key. Values like 0x22101 and 0x11002100 clearly encode state, and decoding them by guesswork is precisely the failure this project refuses (G-3) — so they get their own amber mark, and that mark is a change request to the integrator, not a cable to pull. NOSIG means nothing is historised for that unit at all. Drawing RAW and NOSIG the same would hide the difference between a question and a hole.
