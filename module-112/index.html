The control room has two control paths

What am I looking at, and which system makes the safety decision?
Operator stationWinCC screen: view, alarms, commands
→
PCSProcess control, remote I/O, package interfaces
→
ProcessMotors, valves, measurements
ESD local HMI / IPCSafety status and event analysis
←
Independent ESD PLCEvaluates shutdown causes and effects
←
Safety inputsTrip and fire/gas signals

PCS ↔ ESD communication is informational. The safety logic does not depend on the PCS.

At the console Use WinCC to understand plant state. The ESD acts independently when a safety cause is met.

MODULE 112 · WHAT YOU HAVE

PCS and ESD: read the boundary

If a control-room screen stops updating, does that remove the ESD function?
PCS · S7-1500Normal process control · ET 200SP remote I/O on skids · WinCC operator view
ESD · S7-1500FIndependent protective logic · own local HMI and industrial PC
PCS ↔ ESD: status exchange only · no safety decision depends on WinCC
When status is uncertain: identify the affected screen and time; report it through the site escalation route.
At the console Treat a blank or stale operator view as an information problem that needs escalation; do not assume protection has been lost or proven healthy.
Plant Operating Manual 21044-PR-MAN-00001 Rev.1 §2.2–2.3. Diagram is a simplified system boundary.

MODULE 112 · INFORMATION FAULTS

Three fault symptoms the operator can recognize

What would a communication problem look like on my screen?
Diagnostic alarmA device or communication link reports a fault
BAD valueThe system marks a measurement unreliable
Frozen valueA reading does not move when related process readings do
Cross-check a related reading. Record tag, time and alarm text, then call maintenance.
PROFINET can carry quality status. Modbus does not carry per-value quality; a PLC timeout may still detect lost replies. Actual Tendrara timeout behavior must be verified.
At the console Treat an unexplained BAD or frozen value as suspect; never simulate or force around a fault.
HMI Philosophy 21044-AU-HMI-00002 Rev.1 §7–8; Modbus Application Protocol V1.1b3; operator symptom diagram.

ALARMS & PROTECTION — 01 · CLASSIFY

What does this alarm mean?

First read the tag and message. Priority tells you the kind of alarm; the C&E tells you the protective action.
1 · TRIPAbnormal shutdown for its system
2 · INTERLOCKBlocks or disables an action
3 · WARNINGOutside normal; no trip by itself
4 · DIAGNOSTICEquipment or communication unhealthy

HMI Philosophy colour example. Diagnostic has three proposed colours; the as-built selection is unverified.

A priority number is not a shutdown level.
HMI Philosophy 21044-AU-HMI-00002 Rev.1 §7 pp.7–8.

3 · RESPONDUse the approved operating procedure and control authority

ALARMS & PROTECTION — 04 · PROTECTION

One cause → one defined outcome

A cause selects an outcome in the C&E. These are distinct scopes, not steps in an escalation chain.
ALARMAn event to assess; no shutdown implied
LSDLocal shutdown of the affected group
PSDProcess shutdown defined by its cause
ESDEmergency shutdown defined by its cause
LALL-2201TA-221 low-low level → LSD; loading pumps trip.
LAHH-2201TA-221 high-high level → PSD.
The independent S7-1500F executes the protective logic. PCS/WinCC receives status information; verify the displayed status against the C&E.

ALARMS & PROTECTION — 06 · PACKAGE EXAMPLE

Capture first-out before package Reset

The CommSkids PCS block has its own Silence, first-out and Reset logic. Use this as a package example only.
NEW TRIP / FAILFirst-out stores cause tag, type and time
SILENCEStops new-event horn request; trip stays active
RESETClears trip/alarm/fail and first-out record
When reviewing this package:capture first-out → investigate cause → follow the approved reset procedure → verify state.
Keep general response separate

Acknowledge is a general alarm-handling concept. The CommSkids Reset is a package command; neither removes a live cause.

Commissioning noise

Expected diagnostics can be separated on record. Fire & gas, protection trips and wire-break/short-circuit are never treated as noise.

Which skids use CommSkids, and the exact control-room Reset interaction, need site verification before a live demonstration.

MODULE 112 · AUTHORIZED ACTIONS

Single-drive command: one object, one result

What must you see before and after Start or Stop?
1
IdentifyUnit and motor tag; current feedback and error text.
2
CheckRemote + Manual; readiness and start permissives.
3
CommandOnly the authorized single action for that object.
4
VerifyFeedback changes as expected; no new fault or trip.
Documented example: LALL-2201 low-low tank level blocks loading-pump start until level is restored. A blocked start is information to investigate, not a command to repeat.
Never use a command button to test whether an interlock or permissive is real.
HMI Philosophy Rev.1 §8.1 pp.11, 14; Plant Operating Manual Rev.1 p.52.
MODULE 112 · AUTHORIZED ACTIONS

Local control, Simulation and Override

A control is unavailable or a value looks simulated. What changes?
LOCAL
Panel owns commandCoordinate with the package or field operator; do not assume WinCC can command.
SIM
Signal or object simulatedReport unexpected SIM. Simulation is for controlled commissioning or troubleshooting.
OVERRIDE
Logic owns PID outputRead the stage and state; do not treat this PID mode as a safety defeat.
For an MR compressor package: selector REMOTE = PCS command; LOCAL = panel START / STOP.
Confirm the selected command location with the field party before handing control across the boundary.
Plant Operating Manual Rev.1 §8.7 p.168; HMI Philosophy Rev.1 §8.1, §8.5–8.6.

Handover starts with open work

What must the incoming shift be able to continue safely?
1
Current stateUnit status, active alarms, trips, Manual / Local conditions and diagnostics.
2
Permit statusOutstanding jobs, suspended permits, active isolations and FR-HSE68.

Escalate with facts the receiver can use
